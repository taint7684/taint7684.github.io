How I work

From a vague need to a specification you can test

The same four steps run through every case study, scaled to the project.

  1. Understand

    Elicit needs with interviews, observation and document review. Measure the baseline so the value of the change can be proven later.

  2. Model

    Map as-is and to-be processes in BPMN, then use cases, state machines and data. Exception flows reveal the rules that interviews miss.

  3. Specify

    Write URD, FSD or SRS at field level. Business rules follow EARS ("WHEN…, THE SYSTEM SHALL…"); every story carries acceptance criteria.

  4. Validate

    Trace requirement → rule → screen → test case. Design test scenarios, support SIT/UAT and track defects to closure.
