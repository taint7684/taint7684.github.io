02 · Approach

From a vague need to a specification you can test

Four steps run through every case study. Each one links to where you can see it in practice.

  1. STEP 01

    Understand

    Frame the problem with stakeholders and evidence. Measure a baseline so the value of the change can be proven later.

    See it in HL-OMS
  2. STEP 02

    Analyse

    Read the source — the regulation, the legacy system, the current process — and map as-is and to-be flows to find where the problem really sits.

    See it in EUDR
  3. STEP 03

    Specify

    Write requirements at field level. Business rules use a fixed pattern ("WHEN…, THE SYSTEM SHALL…"); every story carries acceptance criteria.

    See it in Social Insurance
  4. STEP 04

    Validate

    Trace each requirement to a screen and a test, design UAT scenarios, and check that nothing is left unproven.

    See it in Battery 2030
